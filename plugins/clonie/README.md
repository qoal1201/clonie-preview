# Clonie 플러그인

쓰던 AI에서 내 Markdown 자료를 찾아 작업하고, 저장소 보완은 Clonie에서 검토합니다.

**Clonie 앱은 플러그인 없이도 사용할 수 있습니다.** 폴더를 연결하고 자료를 찾고 읽고 직접
고치는 흐름은 앱에서 시작합니다. 이 플러그인은 같은 자료를 외부 AI에서도 쓰고 싶을 때 설치합니다.
로컬 Codex 연결에는 별도 Clonie 계정·API 키·서버·Tunnel 설정이 필요하지 않습니다.

Clonie 1.1.0 이상과 함께 사용하는 로컬 플러그인입니다.
앱과 플러그인의 다운로드는 [공개 저장소](https://github.com/qoal1201/clonie-preview)에서 안내합니다.

**플러그인과 MCP는 다른 층위입니다.** 플러그인은 MCP 서버 연결 설정과 역할별 스킬을 묶은 설치
패키지이고, MCP는 AI가 Clonie의 검색·읽기·변경 제안 도구를 호출하는 규약입니다. Codex용과
Claude Code용 Clonie 플러그인은 같은 로컬 MCP를 사용합니다. Claude에서만 MCP라고 부르는 것이 아닙니다.
저장소의 `mcpb/manifest.json`은 Claude Desktop의 데스크톱 확장용 별도 패키지이며, 위 플러그인을
설치했다고 해당 확장이나 Claude 계정의 원격 커넥터도 설치되는 것은 아닙니다.

## 사용 흐름

1. Clonie 앱을 응용 프로그램 폴더에 설치합니다. MCP는 앱에 포함되어 별도 다운로드가 필요 없습니다.
   이 개발 플러그인은 승인 대기 변경을 지원하는 앱과 함께 사용합니다. 공개 1.0.6은 문서 변경 방식이
   달라 연결 대상이 아닙니다. 플러그인이 앱의 호환 여부를 확인하고 맞지 않으면 업데이트를 안내합니다.
2. Clonie에서 사용할 Markdown 폴더를 선택합니다.
3. 아래 방법으로 플러그인을 설치하고 새 AI 대화에서 활성화합니다. Codex는 해당 화면의 플러그인
   선택을 사용합니다. `@` 선택 등이 제공될 수 있지만 모든 클라이언트에서 같은 방식은 아닙니다.
4. “Clonie에서 이번 작업과 관련된 자료를 찾아 도와줘”처럼 원하는 일을 말합니다.
5. 문서 보완을 요청했다면 Clonie의 **변경**에서 비교·수정·승인합니다. 승인 전에는 원문이 바뀌지 않습니다.

AI의 작업 폴더를 Clonie 저장소와 같게 열 필요는 없습니다. 로컬 연결 도우미는 Clonie 앱에서
선택한 폴더를 읽습니다. 예를 들어 다른 프로젝트의 AI 대화에서도 Clonie에 연결한 포트폴리오를
찾아볼 수 있습니다. 첫 연결에서 실제 `vaultPath`를 확인하며, AI가 일반 파일 도구로 직접 고치면
Clonie의 제안·승인 흐름을 거치지 않으므로 이 플러그인은 MCP 변경 제안을 사용합니다.

GitHub 등 외부 자료는 사용 중인 AI에 연결된 해당 서비스 도구로 읽습니다. Clonie 설치가 GitHub
계정 연결까지 대신하지 않습니다. 자료를 Clonie에 남기도록 요청하면 AI가 출처와 정리한 내용을
함께 제안하고, 앱에서 승인한 뒤 로컬 Markdown으로 보존합니다. 앱 자체의 GitHub 로그인이나
레포 자동 동기화는 현재 기능이 아닙니다.

### Chat·Work·Cowork 지원 범위

Clonie에서 확인한 범위는 다음과 같습니다(2026-09-27).

| 사용 환경 | 현재 상태 |
| --- | --- |
| 로컬 Codex | 저장소 확인·검색·읽기·앱 승인 후 재조회 확인 |
| Work locally | 프로젝트 없는 새 대화에서 검색·읽기·제안·앱 승인·같은 대화의 재조회 확인 |
| Codex CLI | 설치된 플러그인으로 검색·읽기·제안·앱 승인·재조회 확인 |
| Claude Code·Cowork | 설치 구성을 제공하며 실제 계정에서의 사용 검증은 남아 있음 |

Work는 **Work locally**로 시작합니다. 새 대화에 프로젝트를 지정하지 않아도 됩니다.
일반 ChatGPT Chat과 원격 Work는 이 로컬 플러그인의 지원 범위에 포함되지 않습니다.
위 실기는 한 Mac의 시험 자료로 수행했으며, 모든 호스트 버전·다른 Mac의 동작을 보장하지는 않습니다.

외부 AI가 제안을 보내도 다른 AI 계정에 새 대화가 자동 생성되지는 않습니다. AI 대화는 해당
호스트에 남고, Clonie의 변경 탭에는 승인할 문서 제안이 도착합니다.

새 대화에서 먼저 “Clonie의 연결된 저장소 경로를 확인하고, 이번 작업과 관련된 문서 하나를 찾아
읽어줘. 참고한 경로를 알려주고 아직 변경 제안은 보내지 마”로 확인할 수 있습니다. 자료 읽기와
제안 제출이 해당 호스트에서 허용되어야 합니다. `MCP tool call requires approval, but approval
policy is never`가 나오면 실제 호출 전 승인 정책에서 멈춘 것입니다. 플러그인 설치나 스킬 인식
성공만으로 자료를 읽었다고 보고하지 않으며, 승인을 받을 수 있는 대화에서 이어갑니다.
AI는 문서 보완의 판단·작성을 맡고, Clonie는 선택한 저장소의 원문·diff·승인·저장을 담당합니다.
현재 제안에는 작업 제목과 변경 내용이 담기며 AI의 전체 대화·판단 근거가 자동 수집되지는 않습니다.

## 설치

Clonie 앱을 설치하고 한 번 실행해 사용할 Markdown 폴더를 선택합니다.
그다음 사용할 AI에 플러그인을 설치합니다. **공식 플러그인 목록에는 아직 등재되지 않았습니다.**
앱에 동봉된 설치기는 터미널용 Codex CLI가 없으면 설치된 ChatGPT/Codex 데스크톱의 실행 파일을 찾습니다.

```sh
/bin/bash /Applications/Clonie.app/Contents/Resources/CloniePlugin/install.sh codex
# Claude Code를 사용한다면 마지막 인자를 claude로 바꿉니다.
# 사용자 응용 프로그램 폴더에 설치했다면 앱 경로는 다음과 같습니다.
/bin/bash ~/Applications/Clonie.app/Contents/Resources/CloniePlugin/install.sh codex
```

Clonie 1.0.6에는 이 설치기가 없습니다. [릴리스](https://github.com/qoal1201/clonie-preview/releases)에서
1.1.0 이상 앱의 배포 여부를 먼저 확인하세요.

소스를 내려받았다면 이 저장소의 루트에서도 설치할 수 있습니다. AI 도구는 같은 Mac에 있어야 합니다.

Codex:

```sh
codex plugin marketplace add .
codex plugin add clonie@clonie
```

Claude Code:

```sh
claude plugin marketplace add .
claude plugin install clonie@clonie
```

설치 후 AI에 “Clonie의 연결된 저장소 경로와 문서 목록을 보여줘”라고 요청합니다.
실제 `vault_list` 응답의 `vaultPath`가 선택한 폴더인지 확인하고, 문서 하나를 읽어 봅니다.
패키지 설치 성공과 실제 자료 읽기 성공은 별개입니다.

앱에는 별도의 AI 연결 버튼이 없습니다. 처음에는 “Clonie 연결을 확인하고 이 저장소로 작업해줘”라고
요청할 수 있습니다. `clonie-init` 스킬이 앱·선택 폴더·실제 연결을 대조하고 필요한 복구를 진행합니다.
설정 확인 성공을 실제 자료 읽기 성공으로 표시하지 않습니다.

스킬은 요청에 맞춰 AI가 골라 쓰며 같은 과업에서 매번 호출 기호를 반복할 필요는 없습니다.
직접 지정하려면 Codex에서는 `$clonie`·`$clonie-init`, Claude Code에서는
`/clonie:clonie`·`/clonie:clonie-init`을 사용할 수 있습니다. 스킬 호출과 MCP 도구 활성화는 구별합니다.
연결된 도구가 없다면 스킬 이름만으로 자료를 읽을 수 있는 것은 아닙니다.

이전에 수동으로 Clonie MCP를 등록했다면 기존 연결의 경로부터 확인합니다. 새 플러그인의 읽기가
확인된 뒤 중복된 이전 연결만 해당 AI의 설정에서 비활성화합니다. 플러그인이 기존 설정을 삭제하거나
덮어쓰지는 않습니다. 연결 복구를 요청하면 AI가 확인된 Clonie 설정을 고칠 수 있습니다.


## 연결 범위

- 이 플러그인은 로컬 Clonie 앱에 포함된 `clonie-mcp`를 실행합니다. 앱 창은 닫혀 있어도 됩니다.
- 앱은 마지막으로 일반 실행한 Clonie가 등록한 위치에서 찾습니다. 아직 등록하지 않았거나 이동했다면
  `/Applications/Clonie.app`, 그다음 `~/Applications/Clonie.app`에서 찾습니다. QA 앱은 등록하지 않습니다.
- MCP 시작 시 Clonie가 선택해 둔 저장소 하나에 연결합니다. 앱에서 폴더를 바꿨다면 AI 쪽 Clonie
  연결을 다시 시작하고 경로를 확인합니다. 진행 중인 AI 작업의 대상 폴더를 자동 전환하지 않습니다.
- 앱·저장소를 찾지 못하면 오류로 끝납니다. 기본 저장소를 새로 만들거나 자료 폴더를 임의 선택하지 않습니다.
- 앱의 MCP가 `proposal-v1` 변경 계약을 지원하는지 저장소 접근 전에 확인합니다. 옛 즉시 저장 방식의
  앱에 연결해 승인 대기인 것처럼 설명하지 않습니다. 진단 성공은 실제 MCP 조회 성공과 별개입니다.
- Codex의 현재 CLI에는 기존 대화의 MCP 재시작 명령이 없습니다. 플러그인 업데이트 뒤에는 새 대화가
  필요할 수 있습니다. Claude Code는 `/mcp`에서 연결을 확인하고 지원 버전에서는 `/reload-plugins`로
  플러그인 변경을 반영합니다. 호스트에서 제공하지 않는 재연결을 완료했다고 표시하지 않습니다.
- 검색·읽기 요청만으로 저장하지 않습니다. 문서 변경 요청은 승인 대기 제안으로 남습니다.
- MCP 도구에는 읽기 전용 여부·변경 성격을 명시합니다. `vault_write`는 제안 상태를 만들므로
  읽기 전용이 아니며 반복 호출하면 제안이 중복될 수 있습니다. 성공 결과의 구조화된 값과 호환용
  JSON 텍스트는 같은 내용입니다. 도구 설명 정보가 실제 권한이나 Clonie 승인을 대신하지 않습니다.
- AI에 전달한 문서 내용은 해당 AI 서비스에서 처리됩니다. 로컬 MCP라는 이유만으로 AI 처리까지
  오프라인이라고 설명하지 않습니다. 플러그인이 별도 원격 MCP 서버나 자동 대화 수집기를 추가하지는 않습니다.

개발·격리 시험에서는 MCP 실행 환경의 `CLONIE_APP_PATH`에 앱의 절대 경로를,
`CLONIE_VAULT`에 시험 저장소의 절대 경로를 지정할 수 있습니다. 잘못된 명시 경로는 다른 경로로 대체하지 않습니다.

## 개발과 배포

Codex용 `.codex-plugin/plugin.json`과 Claude Code용 `.claude-plugin/plugin.json`이 같은 MCP와
스킬을 사용합니다. Codex는 manifest에 지정한 플러그인 기준 작업 폴더로 실행하고,
Claude Code는 `.mcp.json`의 `CLAUDE_PLUGIN_ROOT`를 해석합니다. 호스트마다 다른 실행 경로 처리를
분리하며 외부 런타임 설치나 앱 바이너리 중복 배포 없이 앱의 MCP를 재사용합니다.
이 플러그인은 macOS용 Clonie 앱이 설치된 기기에서 실행해야 합니다.

앱을 업데이트할 때는 먼저 Clonie를 정상 종료하고 새 앱으로 교체한 뒤 한 번 실행합니다.
앱에 동봉된 설치기를 다시 실행하면 같은 경로의 플러그인 패키지를 설치할 수 있습니다.
플러그인 변경 후에는 새 대화에서 실제 연결 경로를 확인합니다. 앱 파일과 AI의 플러그인 캐시는
별개이므로, 소스를 GitHub에 올렸다는 이유만으로 기존 설치가 자동으로 갱신된다고 안내하지 않습니다.

스킬 원본은 저장소의 `.agents/skills/clonie/`, `.agents/skills/clonie-init/`,
`.agents/skills/clonie-session-record/`입니다. init에는 실행 경로와 진단에 공통으로 쓰는 스크립트가 있습니다.
변경 후 `python3 scripts/sync-clonie-plugin.py`로 배포본을 갱신합니다. gate에서 사본의 일치를 확인합니다.

기존 MIT 권리와 제3자 고지를 보존합니다.
